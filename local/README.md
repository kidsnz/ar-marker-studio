# ローカル版（手元でだけ速いモード）

画面・判定・ヒートマップ・探索は公開版とまったく同じ。**生成だけ**を手元の Node に
肩代わりさせて速くする。

## 使い方

リポジトリの直下にある **`start-local.command` をダブルクリック**する。
ターミナルが 1 枚開いて、ブラウザが自動で `http://localhost:8790/` を開く。

終わるときはそのウインドウを閉じる。

手で動かす場合:

```bash
node local/server.js
```

必要なのは Node v20 以上だけ。`npm install` は要らない。

## 効いているかの見分け方

画面の左下に緑で **「ローカル生成 有効（4スレッド）」** と出る。
出ていなければ公開版と同じくブラウザ内で生成している（＝サーバが動いていない）。

## 速度（実測 / 500x751 の絵）

| | 生成 1 回 |
|---|---|
| 公開版（ブラウザ内・carnaux の asm.js） | 12.0 秒 |
| **ローカル版（Node・4 スレッド）** | **4.2 秒** |

スレッド数は 4 が最速。8 にすると頭打ちになる（8 コアの Mac で実測）。
`THREADS=8 node local/server.js` のように変えられる。

## 中身

```
local/
  server.js         画面を配り、生成の依頼を受ける
  worker.js         生成 1 回ぶんの子プロセス（1 回ごとに使い捨てる）
  local-boost.js    ページに差し込んで Worker を横取りする
  vendor/NftMarkerCreator_wasm.thread.js   生成器（webarkit 版のスレッドビルド）
```

**公開版のファイルは 1 行も書き換えていない。** `server.js` が `index.html` を配る
ときに `<script>` を 1 行足すだけで、生成の呼び出し先が入れ替わる。

## なぜ公開版に載せないのか

同じ生成器の**ブラウザ用ビルド**も試したが、**ブラウザでは asm.js の 2.4 倍遅かった**
（12.0 秒 → 28〜32 秒。実測）。Node で動かすときだけ速い。だから公開版は
carnaux 版のままにして、手元だけこちらを使う。

## 生成結果は公開版と同じか

同じ。実測で確認済み（500x751 の絵、-level=2 -dpi=72）:

| | 合計点 | 縦持ち | 横持ち |
|---|---|---|---|
| 公開版（carnaux） | 205 | 26 | 8 |
| ローカル版（webarkit） | 203 | 26 | 8 |

合計点の 1〜2 点差は浮動小数の丸め。**実際に使う距離帯の点数は一致する。**
Node 版・wasm 版・スレッド版の 3 つは互いにバイト単位で完全一致する。

## 生成器について

[webarkit/Nft-Marker-Creator-App](https://github.com/webarkit/Nft-Marker-Creator-App) 0.4.0
のスレッドビルド。carnaux 版の後継で、入口の名前が違う:

```
carnaux : M._createImageSet(ポインタ, dpi, W, H, nc, 文字列ポインタ)   ← malloc が要る
これ    : M.createNftDataSet(配列, dpi, W, H, nc, 文字列)              ← そのまま渡せる
```

**carnaux 版の「Module を使い回すと 2 回目が 1 回目のまま返る」不具合は直っている**
（level=4 → 10388B、続けて level=0 → 1188B、再び level=4 → 10388B で 1 回目と一致）。

**アルファ付き PNG が壊れる不具合は直っていない。** 背景を塗り潰して RGB にしてから入れること。
